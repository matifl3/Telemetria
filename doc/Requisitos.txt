1. DESCRIPCION GENERAL
--------------------------------------------------------------------
Aplicacion web que recibe archivos de telemetria guardados por
Assetto Corsa (AC1), los interpreta, los divide en vueltas y permite
descargar un CSV por vuelta con las senales de conduccion.

2. OBJETIVO
--------------------------------------------------------------------
Que el usuario obtenga datos de telemetria por vuelta de forma simple,
sin depender de software propietario (MoTeC i2, AiM Race Studio),
para analizarlos, graficarlos o usarlos en su proyecto.

3. ALCANCE
--------------------------------------------------------------------
 - Juego: Assetto Corsa (AC1) unicamente.
 - Entrada: archivos .acreplay (version 16) y .nkt (AiM Race Studio).
 - Modalidad: archivos guardados (post-sesion). Sin captura en vivo.
 - Salida: un archivo CSV por cada vuelta detectada.
 - Interfaz final: aplicacion web local.
 - Primer entregable: script CLI de parseo y exportacion.

 FUERA DE ALCANCE
 - Captura en vivo (UDP puerto 9996 / shared memory).
 - Assetto Corsa Competizione (ACC) y Assetto Corsa EVO (ACE).
 - Comparacion grafica de vueltas, cuentas de usuario, nube.
 - Edicion de archivos del juego.

 FUENTES DE DATOS (entradas)
 - Replay .acreplay (version 16): lo guarda el usuario ("Save Replay") en
   Documents\Assetto Corsa\replay\. Telemetria completa por frame.
 - Export AiM .nkt: lo genera el juego automaticamente al terminar cada
   sesion en Documents\Assetto Corsa\aim\telemetry_dump.nkt. Se
   sobreescribe, hay que copiarlo antes de la proxima sesion. Formato
   propietario (ver RNF-06).
 - Fuera de alcance como entrada: ctelemetry .ct, resultados en out\,
   captura en vivo (shared memory/UDP) y apps de terceros.

4. USUARIOS
--------------------------------------------------------------------
 - Estudiante / piloto que quiere analizar sus vueltas.
 - Docente que revisa el trabajo.
 (Usuario unico, sin autenticacion.)

5. SUPUESTOS
--------------------------------------------------------------------
 S1. El archivo .acreplay es version 16. Otras versiones no se soportan.
 S2. El entorno tiene Python 3.10+ (todo el proyecto: core y web usan el mismo
     lenguaje).
 S3. Los archivos de entrada estan completos (no truncados).
 S4. La app corre en Windows (los archivos se generan en Windows),
     aunque el parseo en si es multiplataforma.
 S5. El formato .nkt es propietario; se documenta como riesgo (ver RNF-06).

6. REQUISITOS FUNCIONALES
--------------------------------------------------------------------
 RF-01 Cargar archivo. El sistema debe permitir subir/indicar un archivo
       de telemetria (.acreplay o .nkt).
 RF-02 Detectar formato. El sistema debe reconocer el formato del
       archivo por su extension y contenido.
 RF-03 Parsear .acreplay v16. Debe leer encabezado, autos y frames
       (ver doc/FormatoTelemetria.md) a objetos tipados.
 RF-04 Parsear .nkt. Debe leer el export de AiM Race Studio (sujeto a
       disponibilidad del formato; ver RNF-06).
 RF-05 Segmentar por vuelta. Debe dividir los frames en vueltas usando
       el numero de vuelta y/o el reinicio de tiempos de vuelta.
 RF-06 Exportar CSV por vuelta. Debe generar un CSV por vuelta con
       columna de tiempo y las senales disponibles.
 RF-07 Listar vueltas. Debe mostrar las vueltas detectadas con su
       numero, tiempo y validez (vuelta lanzada vs. de salida/entrada).
 RF-08 Seleccionar descarga. Debe permitir descargar el CSV de una vuelta
       o de todas.
 RF-09 Identificar sesion. Debe mostrar metadatos: pista, configuracion
       de pista, clima, auto, piloto.
 RF-10 Manejo de errores. Ante archivo invalido, version no soportada o
       datos truncados, debe informar un error claro sin caerse.
 RF-11 Reutilizar el core. La capa web debe usar el core como libreria (import),
       sin duplicar la logica de parseo.

7. REQUISITOS NO FUNCIONALES
--------------------------------------------------------------------
 RNF-01 Lenguaje: Python 3.10+ para todo el proyecto (core y web).
 RNF-02 Plataforma de desarrollo: Windows.
 RNF-03 Dependencias minimas; el parseo usa solo la libreria estandar.
 RNF-04 Rendimiento: un archivo tipico (< 100 MB) debe procesarse en
        pocos segundos.
 RNF-05 Usabilidad: interfaz web sencilla; flujo subir -> elegir -> bajar.
 RNF-06 Riesgo de formato: el .nkt es propietario y no esta documentado
        publicamente. Estrategia: (a) permitir importar el CSV exportado
        por AiM Race Studio, o (b) investigar/reverse-engineering. Es el
        requisito con mayor incertidumbre tecnica.
 RNF-07 Mantenibilidad: codigo modular (lectores, procesamiento, web).
 RNF-08 Testeabilidad: tests unitarios con archivos de muestra.
 RNF-09 Idioma: documentacion e interfaz en espanol.
 RNF-10 Privacidad: procesamiento local; no se suben datos a la nube.
 RNF-11 Integracion: la web importa el core directamente (un solo lenguaje,
        sin subprocess) - ver doc/Arquitectura.md.

8. CASOS DE USO PRINCIPALES
--------------------------------------------------------------------
 CU-01 Convertir replay a CSV por vuelta
   Actor: usuario.
   Precondicion: existe un archivo .acreplay v16.
   Flujo:
     1. Usuario sube el archivo.
     2. Sistema detecta y parsea el formato.
     3. Sistema segmenta las vueltas.
     4. Sistema muestra la lista de vueltas con tiempos.
     5. Usuario descarga el/los CSV.
   Postcondicion: uno o mas archivos CSV por vuelta.

 CU-02 Importar telemetria .nkt
   Actor: usuario.
   Flujo: igual a CU-01 pero con un archivo .nkt.
   Nota: sujeto a RNF-06.

 CU-03 Diagnostico de archivo invalido
   Actor: usuario.
   Flujo: el sistema detecta version no soportada o archivo corrupto y
          muestra un mensaje con la causa.

9. CRITERIOS DE ACEPTACION (v1)
--------------------------------------------------------------------
 - Dado un .acreplay v16 valido, la app genera al menos un CSV por vuelta
   con encabezado y datos, y los tiempos coinciden con los del juego.
 - Dado un archivo invalido, la app muestra un error y no se cuelga.
 - El script CLI (core Python) funciona sin necesidad del servidor web.
 - La web (Flask) procesa un archivo subido usando el core y ofrece la
   descarga del CSV por vuelta.
